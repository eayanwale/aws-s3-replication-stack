## What Was Built

Added `aws_s3_object` resources to upload static assets to the bucket as part of Terraform. This makes the bucket's initial content reproducible — `terraform apply` provisions the bucket AND populates it.

---

## Implementation: `for_each` on Object Resources

Rather than defining one `aws_s3_object` block per file, objects are created with `for_each` over a variable map:

```hcl
resource "aws_s3_object" "assets" {
  for_each = var.s3_objects

  bucket = aws_s3_bucket.main.id
  key    = each.key
  source = each.value
}
```

This makes adding or removing uploaded files a variable change rather than a Terraform resource change.

**Asset directory reorganization:** Files were restructured into subdirectories (`assets/public/`, `assets/static/`) to distinguish publicly served content from static internal assets.

## Hardening Commits on This Branch (before merge)

These commits cleaned up issues found while writing the object upload code:

### Standardize Bucket Naming + Fix Replication Config (`5fa436e`)
Bucket names were inconsistent between the main bucket and replica buckets. Standardized to a shared naming convention. Also fixed a bug in the replication configuration where the destination bucket ARN was being constructed incorrectly.

### Harden Encryption, Object Lock, Lifecycle (`72646c4`)
Tightened the KMS key policy (removed overly broad `*` principals), enforced `delete_protection` on the KMS key, and added `noncurrent_version_expiration` to the lifecycle rule so old non-current versions are eventually deleted rather than just transitioned.

### Rewrite Bucket Policies for Cross-Account Replication (`9ae6c55`)
The existing bucket policies conflicted with cross-account replication — they denied access from principals outside the account, which blocked the replication role. Rewrote policies to allow replication service principals while keeping everything else blocked.

### Fix Public Object Path Resolution + Website Index Compatibility (`a2e25f0`)
The static website `index_document` was set to `index.html` but the uploaded object key was `public/index.html` — S3 website hosting doesn't follow subdirectory `index.html` files unless configured. Fixed by aligning the object key with what the website configuration expects.

### Add Outputs + Documentation (`5ea5648`)
Added `outputs.tf` exposing:
- Bucket ID and ARN
- KMS key ARN
- Regional domain name
- Website endpoint URL

Added `STACK-S3.md` and `STACK-IAM.md` documentation.
