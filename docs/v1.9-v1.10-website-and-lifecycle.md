## v1.9 — Static Website Hosting (STC15-1428)

Added `aws_s3_bucket_website_configuration` to serve the bucket as a static website.

```hcl
resource "aws_s3_bucket_website_configuration" "main" {
  bucket = aws_s3_bucket.main.id

  index_document {
    suffix = "index.html"
  }

  error_document {
    key = "error.html"
  }
}
```

**What this enables:** S3 serves `index.html` when a request hits the bucket's website endpoint URL. Without this configuration, the bucket serves objects by key — there's no concept of a default document.

**Note:** S3 static website hosting serves over HTTP only. For HTTPS, a CloudFront distribution in front of the bucket is required.

## v1.10 — Lifecycle Policy (STC15-1429)

Added `aws_s3_bucket_lifecycle_configuration` to manage object aging:

```hcl
transition {
  days          = 30
  storage_class = "GLACIER"
}
```

**Why:** Once versioning is enabled (v1.5), old object versions accumulate indefinitely. Glacier transition after 30 days moves non-current versions to much cheaper cold storage — Glacier costs ~$0.004/GB/month vs ~$0.023/GB/month for Standard. For objects that are accessed rarely (old backups, audit logs, non-current versions), this is a significant cost reduction.

**Trade-off:** Objects transitioned to Glacier have a retrieval delay of minutes to hours. They are not suitable for active serving. The lifecycle rule should target `noncurrent_version_transition` specifically to avoid sending active objects to Glacier.
