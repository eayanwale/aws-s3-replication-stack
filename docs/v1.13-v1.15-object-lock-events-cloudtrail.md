# v1.13–v1.15 — Object Lock, Event Notifications, CloudTrail

**Branches:** `STC15-1455_Enable_Object_Lock_v1.13` through `STC15-1457_Enable_CloudTrail_Logging_v1.15`

---

## v1.13 — Object Lock (STC15-1455)

Added `aws_s3_bucket_object_lock_configuration` with COMPLIANCE mode default retention.

```hcl
rule {
  default_retention {
    mode = "COMPLIANCE"
    days = 30
  }
}
```

**What Object Lock does:** Prevents objects from being deleted or overwritten for a defined retention period. In COMPLIANCE mode, not even the AWS account root user or Terraform can delete objects before the retention period expires — it's a hard immutability guarantee.

**COMPLIANCE vs GOVERNANCE:**
- GOVERNANCE — users with `s3:BypassGovernanceRetention` permission can still delete; useful for testing
- COMPLIANCE — no bypass possible; used for regulatory requirements (WORM storage for compliance frameworks like SEC 17a-4, HIPAA)

**Prerequisite:** Object Lock must be enabled on the bucket at creation time — it cannot be added later. Versioning is also required.

## v1.14 — Event Notifications (STC15-1456)

Added `aws_s3_bucket_notification` to trigger downstream actions on bucket events.

**What events can trigger:** `s3:ObjectCreated:*`, `s3:ObjectRemoved:*`, `s3:ObjectRestore:*`, `s3:Replication:*`, and more.

**Supported destinations:**
- SNS topic
- SQS queue
- Lambda function

**Use cases:**
- Trigger an image processing Lambda when a new file is uploaded
- Send a notification to an SNS topic when an object is deleted
- Queue objects for downstream processing pipelines

## v1.15 — CloudTrail Logging (STC15-1457)

Added `aws_cloudtrail` to capture S3 data events.

**What's captured:** By default, CloudTrail only logs management events (bucket creation, policy changes). Data events — `GetObject`, `PutObject`, `DeleteObject` — require explicit configuration and incur additional CloudTrail charges.

**Why data events matter:** Management events tell you who changed the bucket configuration. Data events tell you who accessed or modified the objects inside it. For compliance and forensics, data events are often the more important audit trail.

**What CloudTrail stores:** Who made the request (identity ARN), when, from where (IP), what API call, against which resource, and whether it succeeded.
