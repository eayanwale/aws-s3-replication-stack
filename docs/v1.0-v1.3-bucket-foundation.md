# v1.0–v1.3 — S3 Bucket Foundation

**Branches:** `STC15-1237_Create_Bucket_v1.0` through `STC15-1264_Configure_Bucket_Policy_v1.3`
**Period:** Early 2026

---

## v1.0 — Create S3 Bucket (STC15-1237)

Created the initial `aws_s3_bucket` resource and the Terraform scaffolding (provider, variables, backend). The bucket name used the `bucket-usage` variable to distinguish buckets by purpose (e.g. `assets`, `logs`).

No security, versioning, or replication at this stage.

---

## v1.1 — Add force_destroy (STC15-1238)

Added `force_destroy = true` to the bucket resource.

**Why:** `terraform destroy` fails on a non-empty S3 bucket by default. In a dev/staging environment where the bucket is frequently torn down and rebuilt, requiring a manual `aws s3 rm s3://bucket --recursive` before every destroy is friction that adds no value.

`force_destroy = true` tells Terraform to empty the bucket before deleting it. This should be removed (or set to `false`) on any bucket carrying production data.

---

## v1.2/v1.3 — Bucket Policy (STC15-1264)

Added `aws_s3_bucket_policy` to enforce bucket-level access control. The policy controls which principals can perform which actions, independent of IAM identity policies.

**Why bucket policy in addition to IAM:** IAM policies control what an identity can do; bucket policies control who can access the bucket (including cross-account access). Both layers are needed for cross-account and public-access scenarios.

Also introduced the `bucket-usage` variable to integrate into the bucket naming convention.
